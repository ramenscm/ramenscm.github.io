# Fundamentals of VPN: Architecture and How Geo-Unblocking Works

---

### Introduction

Recently, the market has been flooded with various commercial VPN services, led by prominent providers such as NordVPN. However, precisely because these mainstream VPN services are so widely known, their server IP ranges are frequently blacklisted by major streaming platforms like Netflix. 

Furthermore, using small-scale, obscure free VPN services poses substantial security and privacy risks—ranging from data logging to traffic hijacking. For these reasons, I decided to host my own private VPN server and launched a personal project to build a custom OpenVPN environment.

---

### Core Architecture: Client-Server & Tunneling

A VPN (Virtual Private Network) fundamentally relies on a **Client-Server architecture**:

* **Clients**: End-user devices running VPN software.
* **VPN Server**: The central gateway that receives and relays client network traffic.

Through a core networking mechanism called **tunneling**, all packets exchanged between the client and the server are encapsulated and encrypted using protocols such as **SSL/TLS**. From a security perspective, this end-to-end packet encryption operates very similarly to **HTTPS**.

> **Note on Protocol Evolution:**  
> Historically, VPNs were developed primarily to provide strong communication encryption and secure remote access over untrusted networks. Today, because HTTPS is ubiquitous across virtually all web services, end-to-end encryption is already standard. Consequently, the original core necessity of VPNs has somewhat faded from public perception.

---

### How VPNs Bypass Regional Restrictions (Geo-Spoofing)

Instead of pure encryption, VPNs are now most commonly used to access foreign services that are geo-blocked or restricted in the user's physical location. 

The step-by-step workflow is as follows:

1. **Client Connection Initiation**  
   The user opens a VPN client application (e.g., OpenVPN Client) and initiates an encrypted connection to the remote VPN server.

2. **Tunnel & Appliance Association**  
   The user's appliance (endpoint device) establishes a secure virtual tunnel with the VPN server, receiving an assigned virtual IP address.

3. **Packet Relaying (Full Tunneling)**  
   All outbound network traffic from the device—such as YouTube streaming, Google searches, and API requests—is encapsulated and forwarded exclusively through the VPN server.

   * **3.1. IP Masking / Geolocation Rewriting:**  
     Because destination web servers only see the public IP address of the VPN server, hosting the VPN server in a specific country (e.g., South Korea, the United States, or Japan) allows all outgoing packets to appear as legitimate traffic originating from that country.

This masking and packet-relaying process forms the basic operating principle of the commercial VPNs we use every day.
